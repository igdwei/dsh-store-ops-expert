# 数据接入说明

## 一、从收银系统导哪张表

要的是**订单明细**（叫法各家不同：订单明细表 / 结算明细 / 流水明细），一行一个订单，不是日报、不是汇总表。

常见的导出位置：
- 美团收银 / 客如云 / 哗啦啦 / 二维火：报表 → 营业分析 → 订单明细 → 导出 Excel
- 银豹 / 思迅：销售 → 销售流水 → 导出
- 自建 POS：让技术导「订单表 join 支付表」

**一份表最好只含一个门店或一个时间段**，不要跨半年导一张巨表——导入慢，浏览器也存不下。

## 二、必需的三个字段

| 字段 | 说明 | 缺了会怎样 |
|---|---|---|
| 门店名称 | 单店可以是一个固定值 | 没法分店看 |
| 营业日期 | 日期型，或 `2026-10-01` / `2026/10/01` 文本 | **完全导不进来** |
| 实收金额 | 每单的实际到账金额 | **完全导不进来** |

这三列是硬门槛。列名不一致不要紧，导入第二步可以手动指定哪一列是什么。

## 三、强烈建议带的字段（没有也能跑，但会少一半结论）

| 字段 | 缺了会失去什么 |
|---|---|
| **流水金额** | 算不了到手率、优惠率、让利杠杆——整个"活动值不值"的分析全废 |
| **优惠金额** | 同上，且没法做流水去向闭合 |
| 订单编号 | 单量只能按行数估；同一天重复上传无法识别 |
| 客流量 | 算不了客单、人均、进店转化相关的一切 |
| 订单渠道 | 分不了堂食 / 外卖 / 团购，结构分析只剩总量 |
| 餐段 | 分不了早 / 午 / 晚 / 夜宵，排班与备货建议无从下手 |
| 业务类型 | 分不了堂食 / 自提 / 外卖，渠道经济性会混算 |
| 结账时间 | 做不了时段分布，看不出高峰在哪一小时 |

## 四、能自动识别的两类分组列

收银系统常把支付方式和优惠项铺成很多列，这类表有个特征：**第 2 行是分组名**（同一行里"实收组成"重复十几次、"优惠组成"重复九次）。工作台会自动跳过标题行与分组行，并按分组名判断这一列是"支付方式"还是"优惠项"。

| 分组名 | 含义 | 校验方式 |
|---|---|---|
| 实收组成 | 微信 / 支付宝 / 云闪付 / 会员卡值 / 现金… | 各行相加必须等于实收金额 |
| 优惠组成 | 系统优惠券 / 营销优惠 / 商家优惠 / 平台佣金… | 各行相加必须等于优惠金额 |

分组名不是这两个词的，会当成普通列忽略——不会影响对账，只是少一层明细。

## 五、导入的七个坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"缺必需列" | 表头不在第一行（上面有标题、导出时间） | 导入时会自动找表头；还不行就在第二步手动改字段 |
| 日期全部识别失败 | 日期是 Excel 序列号（45xxx）或 `20261001` 这种紧凑格式 | 支持 Excel 序列号与常见分隔符；`20261001` 需要在 Excel 里先转成日期 |
| 金额变成 0 | 金额带货币符号或千分位空格 | 支持 `¥1,234.56`；带"元"字的要在源表去掉 |
| 合计行被算进去 | 表尾有"总计""小计"行 | 导入时会按"门店/日期为空"跳过；仍出现就从源表删掉 |
| 半天数据不见 | `.xls` 老格式 | 只吃 xlsx / csv。`.xls` 请先另存为 xlsx |
| 两个月的表导进去变成一份 | 多文件合并按**日期**去重，后导入的覆盖先导入的 | 正常行为。但同一天拆成两次上传会互相覆盖，**同一份数据不要拆开传** |
| 刷新后数据没了 | 聚合结果超过浏览器存储上限（约 4.2MB） | 按季度拆成几份分别导入；或一次性只留当期数据 |

## 六、多文件合并规则

- 可以一次选多份，也可以把多份拖进来。
- 按「门店 + 日期」判断重叠：同一天出现在两份文件里，**以列表靠下的那份为准**。
- 完全一致记为"重复"，不一致记为"冲突"，导入前会列出来给你确认。
- 会员、退款、客群这几项指标是按文件汇总的，直接相加；重叠期会偏高。
- 移除任意一份，其余数据会立刻重算。

## 七、导入后先看这三件事

1. **对账体检的金额三项是否 0 误差**（流水−优惠=实收、优惠明细合计、支付方式合计）
2. **日期范围对不对**（有没有把上个月的表混进来）
3. **门店数对不对**（连锁客户最容易漏店）

三项都对，再开始看结论。有一项不对，先修数据。
