# 指标口径表

工作台里出现的每一个数字，定义都在这里。**对外解释口径时照这里说，不要临场另编一套。**

---

## 一、六个基础量

| 指标 | 算法 | 说明 |
|---|---|---|
| 流水（gross） | 订单明细「流水金额」求和 | 折前金额。谈"做了多少生意"可以用它，谈"赚到多少"不能 |
| 优惠（disc） | 订单明细「优惠金额」求和 | 含平台佣金类优惠（美团服务费、闪购服务费等），所以「优惠」不等于「我自己让的」 |
| 实收（net） | 流水 − 优惠 | **所有收入结论只用这个数** |
| 平台佣金（comm） | 优惠项里名称含「佣金 / 服务费」的部分 | 刚性成本，不是营销决策，分析时要单列 |
| 单量（orders） | 订单数 | 订单明细的行数（已按订单去重） |
| 客流（guests） | 客流量求和 | 成交客流，不是门前客流 |

> 恒等式：`流水 − 优惠 = 实收`。这条对不上，后面所有结论都不成立，先去「数据」页看对账体检。

---

## 二、四个比率

| 指标 | 算法 | 用在哪 | 易错点 |
|---|---|---|---|
| 到手率 | 实收 ÷ 流水 | 渠道经济性、活动代价 | 外卖天然比堂食低 15–20 个点，必须分渠道看；混算会把结构问题误判成"活动做亏了" |
| 优惠率 | 优惠 ÷ 流水 | 让利是否过量 | 分子含平台佣金。只看这一个数会得出"折扣打多了"这种废话 |
| 单均 | 实收 ÷ 单量 | 量价拆解 | 用的是实收，不是流水；也不是客单价（客单 = 实收 ÷ 客流） |
| 客单 | 实收 ÷ 客流 | 堂食翻台与人均 | 外卖单没有真实客流，混算会失真 |

## 三、三个拆解工具

### 3.1 让利杠杆

```
让利杠杆 = Δ实收 ÷ Δ优惠        （区间 A 相对区间 B）
```

| 取值 | 判断 | 该做什么 |
|---|---|---|
| ≥ 1.5 | 划算，让出去的钱成倍收回 | 可以加码，但先确认增量来自新客还是老客 |
| 1 – 1.5 | 勉强打平，让多少收多少 | 优化门槛与力度，不扩大范围 |
| 0 – 1 | 不划算，让 1 元收不回 1 元 | 先查是哪一项优惠在漏，再决定砍哪一项 |
| < 0 | 反效果，让得更多收得更少 | 立刻停，同时排查是否同期有断货、闭店、差评 |

**前置条件**：Δ优惠 必须明显变动（工作台的判定是 |Δ优惠| ≥ max(¥120, 基期优惠 × 6%)）。优惠几乎没动的时候不谈杠杆——那是噪音。

### 3.2 流水去向闭合

```
Δ流水 − Δ平台佣金 − Δ商家让利 = Δ实收
其中：商家让利 = 优惠总额 − 平台佣金
```

四个数必须能对上，对不上说明口径错了，不是数据错了。

看这张表能一眼分清两件事：
- **佣金涨**：外卖占比升了，属于结构变化，不是活动问题
- **商家让利涨**：自己放的血，属于决策问题，可以调整

### 3.3 量价拆解（连环替代法）

```
量效应 = (本期单量 − 基期单量) × 基期单均
价效应 =  本期单量 × (本期单均 − 基期单均)
量效应 + 价效应 = Δ实收
```

- 量效应为主 → 客流/曝光/复购的问题，动作在获客与复购
- 价效应为主 → 单均/结构/优惠力度的问题，动作在菜单结构与活动门槛
- 两段相加不等于总差 → 计算有误，不要往下推

## 四、周期口径（最容易出错的地方）

| 场景 | 正确做法 | 错误做法 |
|---|---|---|
| 周对比 | **同星期 7 天 vs 7 天**（周一↔周一） | 本自然周 vs 上个自然周（周一对上周五，全是假波动） |
| 跨月对比 | 先折**日均**再比 | 直接比月总额（月长不同，31 天必然比 30 天多） |
| 含长假的区间 | 把假期日从基线剔除，单独说明 | 直接比（国庆 7 天会把基线抬高，正常日子被误判成暴跌） |
| 单日异动 | 跟**同星期**均值比 | 跟"最近 7 天平均"比（把周末混进工作日的基线） |
| 目标对比 | 日/周/月目标都折成日均，再乘区间天数 | 拿月目标直接跟 7 天实际比 |

> 日均是唯一能跨周期比较的量。目标设成什么周期都行，内部统一折日均。

## 五、数据质量相关的三个计数

| 计数 | 含义 | 要不要管 |
|---|---|---|
| 结账时间与营业日期不一致 | 跨零点订单（夜宵单落到次日） | 不用管。这是「经营口径 ≠ 系统时间」，看排班用结账时间，看经营用餐段 |
| 客流量 = 0 的订单 | 多为外卖单或未采客流的通道 | 不用管，但做"客单"时要把这些排掉 |
| 餐段与结账时间冲突 | 凌晨单被系统标成早餐/午餐 | 不用管，属于系统口径问题 |

**只有金额三项（流水−优惠=实收、优惠明细合计、支付方式合计）必须 0 误差。** 上面三项是口径特征，不是数据错误——工作台把它们列出来是为了让你知道"为什么这里对不上"，不是让你去修。
