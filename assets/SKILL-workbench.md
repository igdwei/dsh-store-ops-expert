# 门店经营助手 · 交付与解读

这个技能管三件事：**把工作台文件交给客户、把客户的数据装进去、把屏幕上的数字讲清楚。**

## 一、交付物

`assets/store-ops-dashboard.html` — 交付用这一个文件。

> 交付时只发这一个文件；客户回传截图排障时，让他念一下页面左下角的版本号（当前 v2.6.0）。

单文件 HTML，零外部依赖：双击用浏览器打开即可，不需要安装、不需要联网、**数据不上传**（全部在客户本机浏览器里算）。

内置三家虚构门店、一个月的示例数据，打开就能看到完整看板。客户导入自己的收银明细时，第二步会让客户选「完全覆盖」或「追加合并」：首次导入默认覆盖，示例数据一并清掉，虚构门店不会留在看板里；已有文件后再导入默认追加，日期重叠以新文件为准。

**交付动作**：把 `assets/store-ops-dashboard.html` 复制到客户能取到的位置（桌面或指定目录），告诉客户「双击打开」。不要发文件夹，只发这一个文件。

## 二、客户第一次用，按这个顺序讲

1. **先打开看**：首页默认是示例数据，顶部有一条提示条。看一眼长什么样，就知道值不值得导自己的表。
2. **再确认字段**：让客户从收银系统导一份「订单明细」导出表（xlsx 或 csv）。需要哪些列见 `references/data-import.md`。列名不一致没关系，导入时会自动认，认错可以手动改。
3. **导入**：「数据」页 → 「导入我自己的收银明细」→ 选中文件（可以一次选多份，也可以直接拖进去）。读完表后会问「完全覆盖」还是「追加合并」：换一批全新的数据选覆盖，补几个月历史选追加。
4. **看体检结果**：导入后先看「对账体检」。金额三项（流水−优惠=实收、优惠明细合计、支付方式合计）必须 0 误差。有误差先修数据，不要带着错数据做结论。
5. **设目标**：首页「目标进度」填月目标 / 周目标 / 日目标都行，内部统一折成日均比较。

## 三、工作台的五页各管什么

完整版有五个页面，基础版只有前两个和最后一个：

| 页面 | 回答的问题 |
|---|---|
| **经营** | 这个周期到底怎么样了？和上一周比、和目标比、和同星期比差多少？今天该先管哪件事？ |
| **归因** | 差在哪？量的问题还是价的问题？哪个渠道/餐段贡献的？ |
| **结构** | 钱从哪来、让到哪去？渠道结构、优惠明细、时段分布是什么样？ |
| **行动** | 所以做什么？每条动作对应多少钱，谁来做，做完看哪个数？ |
| **数据** | 这张表能不能用？算了什么、没算什么？数据从哪来？ |

> 交付给客户的是**基础版**（经营 + 数据两页）。归因、结构、行动三页是分析者的工具，客户日常不需要。

## 四、口径：数字怎么来的

所有口径的完整定义在 `references/metrics.md`。压缩成五句话：

1. **实收 = 流水 − 优惠**。流水是折前，实收是到手，两者之间的差额就是让利。谈收入一律用实收。
2. **到手率 = 实收 ÷ 流水**，**优惠率 = 优惠 ÷ 流水**。到手率掉、优惠率涨，说明活动在放血。外卖渠道的到手率天然比堂食低 15–20 个点，必须分开看。
3. **单均 = 实收 ÷ 单量**，**客单 = 实收 ÷ 客流**。量价拆解用的是单量 × 单均，不是客流量。
4. **让利杠杆 = Δ实收 ÷ Δ优惠**。≥1.5 划算、1–1.5 打平、<1 是在贴钱买流水。杠杆 <1 时，第一件事不是停活动，是查钱从哪个优惠项漏的。
5. **跨月只能比日均**（月长不同），**周对比用同星期 7 天 vs 7 天**（周一对周一），**长假必须从基线剔除**（否则正常日子会被判成暴跌）。

## 五、六个高频问题怎么答

客户问法千变万化，落到这六类上。每一类的拆法、话术、容易踩的坑见 `references/diagnosis-playbook.md`：

1. 流水涨了，到手反而少了 — 先算让利杠杆，再查优惠明细
2. 单量涨了，实收没涨 — 量价拆解，看单均掉了多少
3. 某一天特别差 — 同星期基线 + 是否有假期/断货/闭店
4. 活动值不值 — 让利杠杆 + 增量毛利（没有成本数据时只能给流水口径）
5. 外卖占比高了，利润反而低 — 渠道到手率分开算，佣金单列
6. 这个月比上个月差 — 先换成日均，再剔假期

## 六、不能做的事（对客户也要讲）

- 没有成本 / 人工 / 租金 / 水电字段，**算不了毛利、净利、人效、坪效**。工作台「数据」页会明确列出「缺字段，做不了」的清单，不要绕过它硬算。
- 只有一个月数据，**做不了同比**。
- 只有成交客流、没有门前客流，**算不了进店转化率**。
- 只有聚合数据、没有订单号，**同一天重复上传的部分订单识别不出来**（只能按日期去重）。

## 七、升级与排障

- 客户反馈「刷新后数据没了」：检查是否超过浏览器存储上限（聚合结果约 4.2MB），超了要按季度拆成几份导入。
- 客户反馈「列认错了」：导入第二步有「改字段」入口，可以逐份调整字段映射。
- 客户反馈「两天的数重复了」：合并只按日期去重，同一天不要拆成两次上传。
- 需要重新构建工作台：源码与构建脚本在开发工作区，不在专家包内。本技能只负责交付与解读，不负责改代码。
