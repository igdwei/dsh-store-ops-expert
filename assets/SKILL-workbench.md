# 门店经营助手 · 交付与解读

本技能管三件事：**把工作台文件交给客户、把客户的数据装进去、把屏幕上的数字讲清楚。**

## 一、交付物

- `assets/store-ops-dashboard.html`：单文件 HTML，零外部依赖，双击用浏览器打开即可，数据全部在本机浏览器里算，不上传。
- 内置三家虚构门店、一个月的示例数据，打开就能看到完整看板；客户在「数据」页导入自己的收银明细后自动替换。
- `assets/expert.jpg`：专家头像，可用于介绍页或市场素材。

**交付动作**：把 `store-ops-dashboard.html` 复制到用户的工作区（或桌面），告诉用户「双击打开」。不要发文件夹，只发这一个文件。

## 二、客户第一次用，按这个顺序讲

1. **先打开看**：首页默认是示例数据，顶部有提示条；看一眼就知道值不值得导自己的表。
2. **再确认字段**：让客户从收银系统导一份「订单明细」（xlsx / csv），字段见 `references/data-import.md`；列名不一致也没关系，导入时会自动认，认错可手动改。
3. **导入**：「数据」页 →「导入我自己的收银明细」→ 选中文件（可多选、可拖入）。
4. **看体检结果**：导入后先看「对账体检」，金额三项（流水−优惠=实收、优惠明细合计、支付方式合计）必须 0 误差；有误差先修数据，不要带着错数据做结论。
5. **设目标**：首页「目标进度」填月/周/日目标都行，内部统一折成日均比较。

## 三、工作台五页

| 页面 | 回答的问题 |
|---|---|
| 经营 | 这个周期到底怎么样？和上一周、目标、同星期比差多少？今天先管哪件事？ |
| 归因 | 差在哪？量的问题还是价的问题？哪个渠道/餐段贡献的？ |
| 结构 | 钱从哪来、让到哪去？渠道结构、优惠明细、时段分布。 |
| 行动 | 所以做什么？每条动作对应多少钱、谁做、做完看哪个数。 |
| 数据 | 这张表能不能用？算了什么、没算什么？数据从哪来？ |

> 交付给客户的是**基础版**（经营 + 数据两页）；归因、结构、行动是分析者的工具，客户日常不需要。

## 四、口径

完整定义见 `references/metrics.md`，压缩成五句话：

1. **实收 = 流水 − 优惠**；谈收入一律用实收。
2. **到手率 = 实收 ÷ 流水**，**优惠率 = 优惠 ÷ 流水**；外卖到手率天然比堂食低 15–20 个点，必须分开看。
3. **单均 = 实收 ÷ 单量**，**客单 = 实收 ÷ 客流**；量价拆解用单量 × 单均。
4. **让利杠杆 = Δ实收 ÷ Δ优惠**；≥1.5 划算、1–1.5 打平、<1 是贴钱买流水。
5. 跨月只比日均；周对比用同星期 7 天；长假从基线剔除。

## 五、六个高频问题

拆法、话术与坑见 `references/diagnosis-playbook.md`：

1. 流水涨了、到手少了 → 先算让利杠杆，再查优惠明细；
2. 单量涨了、实收没涨 → 量价拆解，看单均掉了多少；
3. 某一天特别差 → 同星期基线 + 假期/断货/闭店；
4. 活动值不值 → 让利杠杆 + 增量毛利（无成本数据时只给流水口径）；
5. 外卖占比高、利润反而低 → 渠道到手率分开算，佣金单列；
6. 这个月比上个月差 → 先换日均，再剔假期。

## 六、不能做的事（对客户也要讲）

- 没有成本/人工/租金/水电字段，算不了毛利、净利、人效、坪效；工作台「数据」页会列出缺字段清单。
- 只有一个月数据，做不了同比。
- 只有成交客流、没有门前客流，算不了进店转化率。
- 只有聚合数据、没有订单号，同一天重复上传识别不出来（只能按日期去重）。

## 七、升级与排障

- 刷新后数据没了：检查浏览器存储上限（聚合结果约 4.2MB），超了按季度拆几份导入。
- 列认错了：导入第二步有「改字段」入口。
- 两天的数重复了：合并只按日期去重，同一天不要拆两次上传。
- 需要重新构建工作台：源码不在本插件内，本技能只负责交付与解读。
